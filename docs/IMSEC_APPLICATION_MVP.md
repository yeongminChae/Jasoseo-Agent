# iM증권 2026 신입 IT — 실제 자기소개서 검토 실행 가이드

> **상태:** 여러 문항을 독립적으로 일괄 검토하는 `application-review` 코드와 오프라인 회귀 테스트가 구현되었습니다. 아직 실제 iM증권 문항·개인 초안으로 실행한 결과는 없습니다. 프로젝트 자체가 자기소개서를 작성하거나 채용 합격 가능성을 예측하지는 않습니다.

## 1. 로컬 비공개 입력만 준비

문항은 반드시 **공식 지원서에 표시되는 문장 그대로** 복사하세요. JD(공고)는 원문 관련 부분을 붙이고, 기존 AI 첨삭·탈락 분석·Gold 정답을 이 입력에 섞지 마세요. 타인 개인정보(이름·연락처·사번·고객정보)와 내부 회사 비공개 자료를 포함하면 안 됩니다. 외부 모델로 전송할 내용은 본인이 선별·마스킹하세요.

```bash
mkdir -p private/imsec
${EDITOR:-vi} private/imsec/application.json
```

다음 JSON 구조를 편집해 `private/imsec/application.json`으로 저장하세요. **괄호 안 예시 문자열은 실제 공식 문항과 검증된 본인 초안으로 반드시 교체해야 합니다.** `questions`는 1~6개까지 가능합니다.

```json
{
  "application_id": "imsec_2026_it",
  "company": "iM증권",
  "role": "2026 신입 IT",
  "job_posting": "이 필드를 iM증권 공식 채용공고의 IT 우대사항 및 핵심 요구사항 원문으로 교체하세요.",
  "questions": [
    {
      "question_id": "q1",
      "prompt": "이 필드를 실제 지원서의 첫 번째 자기소개서 질문 원문으로 교체하세요.",
      "draft": "이 필드를 실제 본인이 작성한 첫 번째 문항의 익명화된 초안으로 교체하세요."
    }
  ]
}
```

이 JSON은 생성 예시일 뿐이며 **iM증권의 실제 자소서 문항이 아닙니다**. `q2`, `q3` 등 문항이 있으면 `questions` 배열에 이어 붙이세요.

`private/`와 `runs/`은 프로젝트의 `.gitignore`에 설정되어 있습니다. `application-review`는 요청이 `private/` 아래에 있고 결과 경로가 `runs/` 아래인 경우만 허용합니다. 출력 경로가 비어 있지 않으면 덮어쓰기 전에 중단합니다. `git add -f` 등으로 실수로 강제 커밋하지 마세요.

## 2. 먼저 로컬 미리보기 (AI 호출/전송 없음)

```bash
./.venv/bin/python -m career_ax application-review \
  --request private/imsec/application.json --dry-run
```

이 명령은 문항 ID별 초안 길이, SHA256과 예상 모델 호출 개수만 표시하고 **질문 본문과 자소서 내용은 출력하지 않습니다**. 각 문항의 정상 호출은 Analyst+Critic 2회, 재시도까지 최악 4회이므로 4문항이면 정상 8회, 상한 16회입니다. Codex 플랜의 사용 한도와 실제 모델은 계정 설정에 따라 달라질 수 있습니다.

필요하면 원본을 별도로 열어 외부로 전송될 글과 개인정보 마스킹을 확인하세요. **실행 허가 플래그만으로 자동 전송되는 작업이 아니라, 아래 두 번째 명령을 실제로 실행해야 전송됩니다.**

## 3. 실모델 검토 (명시적 승인 이후에만)

```bash
./.venv/bin/python -m career_ax application-review \
  --request private/imsec/application.json \
  --runner codex \
  --allow-external-model \
  --allow-private-input \
  --timeout-seconds 180 \
  --output-dir runs/private/imsec-v1
```

이 명령은 **외부 모델로 문항·초안·채용공고 발췌문을 보냅니다**. `--allow-external-model`과 `--allow-private-input`이 동시에 필요합니다. Codex CLI는 본인 ChatGPT 계정으로 로그인한 경우 해당 인증을 사용하며 OpenAI API 키를 필요로 하지 않습니다. 다만 실제 모델명·토큰 소비량은 이 도구가 확인하지 않습니다. 의도치 않은 민감정보를 전송하지 않도록 먼저 직접 확인해야 합니다.

출력 예시:

```text
runs/private/imsec-v1/
  summary.json
  summary.md
  q1/review.json
  q1/review.md
  q2/review.json
  q2/review.md
```

`summary.md`는 문항별 검토 보고서를 여는 목차이고, `summary.json`은 문항별 역할 실행 상태·Finding 개수·SHA256을 기록합니다. `review.md`에는 근거가 달린 지적들이 나옵니다. `COMPLETE`는 모델 응답 형식과 인용 위치 검사에 통과했다는 뜻일 뿐, **내용이 옳거나 제출해도 안전하다는 판정이 아닙니다**.

## 4. 수정 → 전후 비교

각 문항의 지적을 아래 방식으로 직접 판정하세요.

1. 문항에서 실제로 요구한 내용을 놓쳤는가? (문항 원문 확인)
2. POS 거래 예외, Spring 실무, 결제 시뮬레이터 등의 경험이 검증 가능한 사실로 쓰였는가? (상용 금융망 운영 경험으로 과장 금지)
3. 증권 IT와의 연결이 구체적인가? (배치 부서·업무를 추정해 단정하지 않기)
4. AI 지적이 질문과 무관한 오탐인가? (필수 결함과 선택적 개선 구분)

수정된 초안은 원본 파일을 덮어쓰지 말고 `private/imsec/application-v2.json`으로 복사·수정합니다. `application_id`를 `imsec_2026_it_v2` 등으로 바꾼 뒤 `--dry-run`부터 재확인합니다. 실제 2차 모델 호출은 **다시 명시적으로 승인한 경우에만** 수행하고 `runs/private/imsec-v2`에 별도 저장합니다.

두 실행 결과는 SHA256이 달라야 하며, 이는 입력 변경 증거일 뿐 수정이 좋아졌다는 증거는 아닙니다. 문항별 수정 근거와 본인 평가를 추가 기록하면 실제 사용 사례로 제시할 수 있습니다.

- Python/LangGraph 기반 두 역할의 독립 Codex 실행, 소스 인용 구조 검증

기능 미구현: 전체 과거 65건 자동 수집·복원, RAG, 자동 자소서 작성, 결과 의미 검증, 지원서 최종 안전 승인, 모델별 비용 계측. 회사의 서류 탈락 원인을 알 수 없으므로 이 시스템이 합격 가능성을 높였다고 단정하지 않습니다.
