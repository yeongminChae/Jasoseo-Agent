# AX Pilot — Engineering decisions / limitations

1. **Research Lead ≠ Orchestrator**: Lead proposes `Plan` and `Decision` JSON. Python validates citation IDs, topic linkage, limits, immutable input snapshot and status transitions. Lead has no DB or file modification tool.
2. **Collector**: lexical search produces bounded candidate lines. The collector selects verbatim `EvidenceRef` objects, and the registry verifies exact source ID, line, quote. No vector database; lexical misses are expected.
3. **Analyst vs Critic**: both invoked with the same original packet; neither receives the other's output. No adjudicator labels, retrospective reports or verdict are passed during T0. Separate `codex exec` calls mean separate CLI invocations; not persistent worker processes.
4. **Runtime verification ≠ Eval**: Pydantic and SHA/citation checks catch malformed or fabricated references and invalid transitions. They **cannot establish correctness of semantic judgments**. An Eval with frozen cases, adjudicated labels and blinded inputs is a separate planned step. No new baseline performance numbers from this pilot.
5. **Progress**: continuation requires a cited prior finding ID, textual topic overlap, non-identical next question and a maximum of 3 cycles. This is a basic heuristic; semantic progress requires human/Eval assessment. A loop that generates questions is not proof of new knowledge.
6. **T0 boundary**: `--scope replay_t0` includes ONLY `phase=t0_input`; `--scope audit` adds the historical `t0_output` but excludes `posthoc`; `--scope research` includes posthoc and cannot claim to replay original T0. T0 stage boundaries are about time of available evidence, not about the file's publication date alone.
7. **Storage**: the source manifest and file bytes are SHA-256 fingerprinted. SQLite commits each completed cycle atomically; a process dying mid-cycle may repeat agent calls on resume. This is *at-least-once* behavior, not guaranteed exactly-once. Source bytes remain read-only.
8. **Retry & budget**: initial pilot implements bounded call count (`max_calls`) and 3-cycle limit; CLI subprocess has timeout. Transient agent/timeout failures are retried at most once by default; all attempts count toward the call ceiling and are logged. Repeated attempts may produce additional model charges. USD/token exact metering is **not implemented** (`null`). The call ceiling bounds count, *not total billing*.
9. **Privacy**: generated run DB and reports are ignored by Git. `--runner codex` explicitly requires `--allow-external-model`, because document excerpts may be sent to the model. The read-only sandbox is defense in depth and **not a guarantee against prompt injection/exfiltration**. Model calls should use redacted extracts.
10. **Synthetic demonstration**: `MockRunner` is deterministic code, not AI. The fixture is fabricated for software testing and not evidence regarding R03/R04 or any real company. The initial Phase 3 historical Eval was not a fresh LLM baseline. Real R03/R04 replay requires point-in-time PDF/PNG originals and documented masking/approval.
11. **Limitations deliberately deferred**: PDF and image extraction/OCR, causal inference about rejection, complete candidate data recovery, FTS5/embeddings, multiuser API/UI, model-agnostic cost metering, asynchronous distributed task workers, blind gold-set evaluation. Not shipping these prevents fake end-to-end claims.
